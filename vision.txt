# Build: Agentic-First Multidisciplinary Oncology Team

You are a senior product engineer, AI architect, and UX engineer.

Build a working, visually compelling prototype of an **agentic-first oncology multidisciplinary team meeting (MDT)**.

This is NOT primarily a chatbot demo.

It should feel like we have reimagined the multidisciplinary meeting around agents:

- a central MDT meeting is underway;
- each clinical role has its own specialist agent and role-specific workspace;
- the chair/orchestrator moves the meeting through a structured process;
- when a case starts, all participating workspaces react;
- specialist agents autonomously inspect the relevant patient information;
- they use tools, evidence and role-specific knowledge;
- humans can observe and steer their specialist agent;
- specialist agents publish structured positions into the shared MDT;
- the system identifies agreement, disagreement, uncertainty and missing information;
- the chair focuses subsequent discussion only on unresolved friction;
- when sufficient convergence is reached, a proposed multidisciplinary treatment plan emerges;
- participants review/sign off or object;
- the final decision and provenance are captured.

The prototype should make this process VISUALLY OBVIOUS.

A viewer should understand the basic idea within 30 seconds without needing an explanation.

This is an "art of the possible" prototype, not a production clinical system.

Do not overbuild authentication, infrastructure, FHIR servers, EHR integration, etc.
Mock components where necessary, but make the agent interaction and orchestration real enough to demonstrate.

----------------------------------------------------------------------
1. PRODUCT THESIS
----------------------------------------------------------------------

Traditional MDT:

    patient data
        ↓
    people manually inspect information
        ↓
    meeting
        ↓
    specialists verbally contribute
        ↓
    disagreement / questions
        ↓
    somebody researches
        ↓
    decision

Agentic-first MDT:

                    PATIENT
                       │
                       ▼
                ┌──────────────┐
                │ MDT CHAIR /  │
                │ ORCHESTRATOR │
                └──────┬───────┘
                       │
              activate patient case
                       │
        ┌──────────────┼───────────────┐
        ▼              ▼               ▼
   Radiology       Oncology        Surgery ...
   workspace       workspace       workspace
        │              │               │
     agent           agent           agent
        │              │               │
        └──── structured positions ────┘
                       │
                       ▼
               SHARED MDT STATE
                       │
              consensus analysis
                       │
              ┌────────┴────────┐
              ▼                 ▼
          CONSENSUS          FRICTION
              │                 │
              │          targeted second
              │              round
              │                 │
              └────────┬────────┘
                       ▼
                PROPOSED PLAN
                       │
                role sign-off
                       │
                       ▼
                MDT DECISION


The central concept is:

    Agents do the work.
    Humans supervise, steer and intervene where judgment is needed.
    The MDT is where specialist positions converge.

Do NOT implement this as one giant agent pretending to be multiple people.

Roles must have distinct context, tools, prompts, state and outputs.

5. ROLE-SPECIFIC AGENTIC UI
----------------------------------------------------------------------

Every specialist workspace has:

1. ROLE-SPECIFIC PATIENT VIEW
2. SPECIALIST AGENT
3. VISIBLE REASONING TRACE
4. EVIDENCE
5. HUMAN STEERING
6. DRAFT POSITION
7. PUBLISH/UPDATE STATUS

Do NOT expose raw model chain-of-thought.

Instead expose a structured, inspectable reasoning trace:

CURRENT ASSESSMENT
    "Lesion demonstrates significant interval growth."

OBSERVATIONS
    - lesion now 23 mm
    - previous scan: 17 mm
    - interval: 11 weeks
    - morphology changed
    - no obvious metastatic disease

WORKING HYPOTHESIS
    "Growth kinetics increase concern despite borderline morphology."

UNCERTAINTIES
    - measurement variation?
    - inflammatory explanation?
    - previous scan quality lower

EVIDENCE BEING CHECKED
    [study]
    [guideline]
    [previous image]
    [patient history]

NEXT ACTION
    "Compare volumetric growth and review previous imaging."

The trace should visibly change as the agent works.

----------------------------------------------------------------------
6. HUMAN ↔ AGENT COLLABORATION
----------------------------------------------------------------------

The clinician should be able to steer their agent.

Examples:

    "Focus on rate of growth."

    "Compare this against the scan from six months ago."

    "Check whether previous toxicity changes your recommendation."

    "I don't agree. Look again at the inferior margin."

    "Find evidence specifically for patients over 70."

    "Check Dutch rather than US guidance."

The UI should then visibly show:

    HUMAN GUIDANCE RECEIVED
              ↓
    AGENT REASSESSING
              ↓
    UPDATED ASSESSMENT

The important idea:

The human is not merely accepting/rejecting an AI answer.

They are collaborating with an agent during specialist reasoning.

----------------------------------------------------------------------
7. AUTONOMY MODEL
----------------------------------------------------------------------

Do NOT require a human click for every agent action.

The system is deliberately agentic-first.

Every conclusion/subtask should have an autonomy state:

    AUTO
    REVIEW
    ESCALATE

AUTO:
Agent considers evidence sufficiently clear and can publish its position automatically.

REVIEW:
Agent can formulate a position but wants specialist review.

ESCALATE:
Agent believes expert judgment is required.

Example:

    RADIOLOGY

    Finding:
    "Clear progression compared with previous imaging."

    Confidence: HIGH
    Mode: AUTO

versus:

    Finding:
    "Borderline progression; measurement and morphology conflict."

    Confidence: MODERATE
    Mode: ESCALATE

    Why:
    - growth rate significant
    - morphology ambiguous
    - decision changes treatment path

The prototype is NOT making real medical decisions.

This autonomy classification is demonstration behavior.

----------------------------------------------------------------------
10. THE CHAIR / ORCHESTRATOR
----------------------------------------------------------------------

Create an MDT Chair Agent.

The Chair is NOT another medical specialist.

Its job is process orchestration.

Responsibilities:

- activate patient
- establish clinical question
- determine relevant roles
- delegate analysis
- monitor role progress
- collect positions
- detect disagreement
- detect missing evidence
- identify uncertainty
- identify unanswered questions
- focus discussion
- request targeted follow-up
- determine whether another round is needed
- synthesize proposed plan
- request concurrence / objections
- capture final MDT outcome

The chair should NEVER simply decide:

"Treatment X is correct."

Instead:

"Current specialist positions indicate convergence around X.
One unresolved concern remains regarding Y."

----------------------------------------------------------------------
11. ROUND-BASED MDT ORCHESTRATION
----------------------------------------------------------------------

Model the meeting approximately as a state machine:

CASE_LOADING
    ↓
INITIAL_ANALYSIS
    ↓
POSITION_COLLECTION
    ↓
FRICTION_ANALYSIS
    ↓
    ├── no blocking friction ──→ PLAN_PROPOSAL
    │
    └── blocking friction
              ↓
       TARGETED_DISCUSSION
              ↓
       POSITION_UPDATE
              ↓
       FRICTION_ANALYSIS
              ↓
             ...

Eventually:

PLAN_PROPOSAL
    ↓
CONCURRENCE
    ↓
    ├── objections → TARGETED_DISCUSSION
    │
    └── concurrence → DECISION_CAPTURED

Make the state machine visible on the central screen.

----------------------------------------------------------------------
12. FRICTION ENGINE
----------------------------------------------------------------------

This is one of the most important features.

The system should actively identify where specialists disagree.

Example:

RADIOLOGY:
    "Imaging suggests progression."

ONCOLOGY:
    "Evidence for changing systemic therapy is insufficient."

SURGERY:
    "Potentially resectable."

RESEARCH:
    "Relevant evidence exists but population differs from patient."

Instead of displaying four paragraphs, synthesize:

FRICTION #1

    IS THIS SUFFICIENT EVIDENCE OF PROGRESSION
    TO CHANGE TREATMENT?

    Radiology       → YES
    Oncology        → UNCERTAIN
    Surgery         → CONDITIONAL

    Missing:
    - pathology confirmation
    - applicability of study X

Then the Chair launches ROUND 2 only for relevant roles.

This is a major part of the demo.

The system should visibly transform:

    3 open questions
            ↓
    2 open questions
            ↓
    1 open question
            ↓
    CONSENSUS

13. RESEARCH AGENT
----------------------------------------------------------------------

Create a dedicated evidence/research agent.

It should behave like a strong medical evidence researcher rather than generic web search.

PRIORITIZE EUROPE.

Source hierarchy approximately:

1. Netherlands
2. European Union / European professional societies
3. International peer-reviewed evidence
4. United States
5. Emerging/preprint evidence

Relevant sources include:

Netherlands:
- Richtlijnendatabase
- IKNL where applicable
- Dutch professional society guidance where applicable

Europe:
- ESMO
- EMA
- CTIS
- European HTA information where relevant

Research:
- PubMed
- PubMed Central
- systematic reviews
- peer-reviewed journals

Trials:
- CTIS FIRST
- ClinicalTrials.gov SECONDARY
- WHO ICTRP where useful

Emerging:
- medRxiv
- bioRxiv where scientifically relevant

US sources:
- NCCN
- ASCO
- FDA
- ClinicalTrials.gov

US information should be clearly marked as US context rather than silently treated as European standard of care.

14. EVIDENCE SCRUTINY
----------------------------------------------------------------------

The Research Agent should not merely retrieve papers.

For each important item assess:

- source authority
- study type
- peer review status
- study population
- sample size
- endpoints
- absolute effect where available
- relative effect where available
- confidence intervals
- follow-up
- subgroup relevance
- post-hoc versus prespecified analysis
- conflicts of interest/funding where available
- similarity to THIS patient
- geographic/regulatory relevance
- recency
- conflicting evidence

Represent evidence with badges such as:

    GUIDELINE
    RCT
    META-ANALYSIS
    OBSERVATIONAL
    CASE SERIES
    PREPRINT

and:

    HIGH PATIENT MATCH
    PARTIAL PATIENT MATCH
    LOW PATIENT MATCH

and:

    NL
    EU
    INTERNATIONAL
    US

18. MEMORY
----------------------------------------------------------------------

Introduce role-scoped and clinician-scoped memory.

But distinguish memory categories.

Example:

FACTUAL / PATIENT MEMORY
    "Previous treatment caused grade 3 toxicity."

INSTITUTIONAL PRACTICE
    "This center normally requests X before Y."

CLINICIAN PREFERENCE
    "Clinician frequently requests growth-rate analysis in borderline lesions."

EXPERIENTIAL NUDGE
    "Clinician previously raised concern about X in similar cases."

Never silently transform anecdotal experience into medical fact.

Render memory explicitly:

    MEMORY NUDGE

    "You previously considered rapid growth particularly important
     in borderline lesions."

    Source:
    MDT case #...
    clinician note
    date

    [Use]
    [Ignore]
    [Inspect]
    [Forget]

Memory should behave as a NUDGE, not hidden policy.

24. FINAL CONVERGENCE
----------------------------------------------------------------------

When the Chair determines that blocking friction has been resolved:

central screen changes dramatically.

Display:

    PROPOSED MDT PLAN

Then every relevant specialist workspace receives:

    MDT PROPOSED PLAN

    [CONCUR]
    [OBJECT]
    [CONCUR WITH COMMENT]

Agents may autonomously concur where policy allows.

Humans are surfaced when review/escalation rules require them.

If somebody objects:

    ObjectionRaised

and the system returns to:

    TARGETED_DISCUSSION

If all required concurrence is obtained:

    MDT PLAN AGREED

Show provenance:

- participating roles
- agent/human contributions
- evidence used
- unresolved uncertainty
- dissent if any
- relevant guidelines
- timestamp
- final decision

26. TECHNOLOGY
----------------------------------------------------------------------

Choose a stack optimized for rapid implementation and excellent UX.

Suggested:

Frontend:
- React / Next.js
- TypeScript
- modern component library
- excellent motion/transitions
- WebSockets or SSE

Backend:
- Python FastAPI OR TypeScript
- simple persistent state
- event bus
- WebSocket/SSE delivery

Agents:

Prefer clean abstraction around the model/runtime.

Possible implementations include:

- Microsoft Agent Framework
- GitHub Copilot SDK where it adds useful interactive agent capabilities

- lightweight custom agent loop

Do NOT introduce a heavy multi-agent framework merely because it exists.

The architecture should make clear:

    Agent runtime != MDT orchestration.

The MDT state machine/event model is OUR application architecture.

Agents participate in it.

    what requires human judgment

But never expose raw hidden model chain-of-thought.

Use concise structured reasoning artifacts.

33. CORE DEMO MESSAGE
----------------------------------------------------------------------

The prototype should make this conceptual transition obvious:

TODAY:

    Humans run the MDT.
    Software supplies information.

AGENTIC-FIRST:

    Agents continuously assemble, investigate,
    challenge and reconcile the case.

    Humans contribute judgment where judgment
    materially changes the outcome.

The multidisciplinary team remains multidisciplinary.

What changes is that every participant now has an agent working through
their professional lens, while a shared orchestration layer continuously
turns those specialist perspectives into a coherent clinical discussion.

----------------------------------------------------------------------

Before coding:

2. Select the smallest sensible architecture.
3. Write a short implementation plan.
4. Define the event model.
5. Define MDT state.
6. Define Position / Claim / Evidence / Friction schemas.
7. Define the scripted patient scenario.
8. Define role-specific views.
9. Implement the central MDT screen FIRST.
10. Implement one excellent role workspace: Radiology.
11. Wire Radiology → MDT event flow.
12. Add Research and Protocol agents.
13. Add remaining specialist roles.
14. Add friction detection.
15. Add targeted second round.
16. Add concurrence.
17. Add memory nudges.
18. Polish animation and demo timing.

Do not begin by building infrastructure.
